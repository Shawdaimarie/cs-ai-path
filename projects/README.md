# Projects

One capstone per tier. Each is defined in the tier's own README; this page is the index and the standard they're held to.

| Tier | Capstone |
|------|----------|
| 01 · Programming | A command-line tool that solves a real problem for you |
| 02 · Systems | A deployed web service with a database and an architecture write-up |
| 04 · Machine Learning | An end-to-end ML project with an honest written report |
| 05 · Deep Learning | A model trained on data you assembled yourself |
| 06 · LLMs & Alignment | A fine-tuned model with a published eval set and documented failures |

Tiers 00 and 03 have checkpoints but no capstone.

## The standard

Every capstone should be something you'd be comfortable showing in an interview. That means:

- **Finished.** A small thing that works beats a big thing that almost does.
- **Documented.** A stranger can clone it and run it from the README alone.
- **Honest.** Limitations and failures are written down, not hidden.
- **Yours.** Following a tutorial is practice. A capstone is a problem you chose.

## Sharing yours

Once a capstone is on your GitHub, you're welcome to open a pull request adding a link to a `SHOWCASE.md` in this folder. Keep the entry to one line: tier, project name, link.
